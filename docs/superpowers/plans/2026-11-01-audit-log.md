# Audit Log Berantai Hash (FR-54) — Rencana Implementasi

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Setiap perubahan kredensial di backend tercatat di log audit append-only berantai hash per gedung, ditulis atomik bersama perubahannya dan dapat diverifikasi.

**Architecture:** Migrasi `0005_audit_events.sql` (tabel + trigger append-only), helper hash dan `AppendAudit`/`VerifyAuditChain` di paket `store`, lalu pemanggilan dari handler enrolment, provisioning, dan perpanjangan di dalam transaksi `Idempotent` yang sudah ada.

**Tech Stack:** Go 1.24+, PostgreSQL 16 (pgx), `crypto/sha256`.

**Spec:** [`docs/superpowers/specs/2026-11-01-audit-log-design.md`](../specs/2026-11-01-audit-log-design.md); ADR-0024; SDD §8.1, §8.3; FR-54.

## Global Constraints

- Hash = SHA-256(`"ANP1-AUDIT"` ‖ prev_hash ‖ u64be(seq) ‖ field(chain) ‖ field(at RFC 3339 nano UTC, presisi mikrodetik) ‖ field(actor) ‖ field(action) ‖ field(subject) ‖ field(JSON kanonik data)); field = u32be(len) ‖ byte.
- Genesis: prev_hash 32 byte nol, seq 1. `chain` = `site:<uuid>` atau `platform`.
- Audit ditulis dalam transaksi bisnis yang sama; audit gagal → transaksi gagal (500, tanpa detail).
- Tidak ada identitas kartu fisik mentah, kontak, atau GPS di `data` (CLAUDE.md aturan 6).
- `ANASTROPHE_REQUIRE_PG=1 go test ./...` dan `go vet ./...` hijau di setiap task.

## Review Focus

1. **Penambahan bersamaan di gedung yang sama.** Dua transaksi paralel tidak boleh menghasilkan seq ganda atau cabang rantai. Test: Task 1, `TestAuditBersamaanTetapBerantai`.
2. **Manipulasi oleh DBA.** Baris yang diubah atau dihapus dengan trigger dimatikan harus terdeteksi di seq yang tepat. Test: Task 1, `TestAuditManipulasiTerdeteksi`.
3. **Audit tanpa perubahan bisnis, atau sebaliknya.** Bila insert audit gagal, kredensial tidak tersimpan. Test: Task 2, `TestAuditGagalMembatalkanProvisioning`.
4. **Data pribadi bocor ke audit.** Baris audit provisioning hanya memuat field yang diizinkan. Test: Task 2, `TestAuditTanpaDataPribadi`.
5. **Retry idempoten mencatat dua kali.** Retry dengan Idempotency-Key sama tidak menambah baris audit. Test: Task 2, `TestRetryIdempotenTidakMenggandakanAudit`.
