# 2026-11-01 — Enrolment via undangan

Keputusan: [ADR-0033](../decisions/ADR-0033-fokus-enrolment-undangan.md) (fokus) dan [ADR-0035](../decisions/ADR-0035-undangan-berkartu-menyetujui-instance.md) (undangan berkartu menyetujui enrolment yang menunggu). Spesifikasi: `docs/superpowers/specs/2026-11-01-undangan-design.md`; rencana: `docs/superpowers/plans/2026-11-01-undangan.md`.

## Perubahan

- **Store (migrasi 0009):** tabel `invitations` dan `card_instances.invitation_id`.
  - Token: 32 byte acak dalam base64url (43 karakter). Yang disimpan hanya SHA-256-nya.
  - Pemakaian tunggal: baris undangan dikunci `FOR UPDATE`, dan undangan dianggap terpakai selama punya instance yang tidak `ABANDONED`.
  - Zona: kartu terdaftar, lalu undangan, lalu kebijakan gedung, *fail-closed*.
- **HTTP:** `POST /v1/enrollments` menerima tepat satu dari `card` atau `invitation`.
  - Undangan tak dikenal, kedaluwarsa, terpakai, atau yang kartunya keluar dari registri dijawab identik 404 `ENR-INVITATION-INVALID`.
  - Hash idempotency memakai hash token.
- **CLI `invite`:** token dicetak sekali.
  - Identitas kartu dibaca dari `--card-file <berkas>|-` (stdin), tidak pernah dari argumen.
  - `--zones` hanya untuk undangan tanpa kartu.
- **App:** `InvitationLink.token(from:)`, `createEnrollment(deviceID:invitation:)`, teks ID/EN untuk `ENR-INVITATION-INVALID`, dan argumen lab `-ANLabInvite`.

## Bukti

- Go: 10 paket lulus dengan PostgreSQL, `go vet` bersih.
- Swift: host 260 test, simulator 258 test (masing-masing 1 dilewati).
- Uji mutasi tertangkap untuk:
  - parser tautan: skema, segmen `i`, panjang, alfabet, jumlah segmen;
  - validasi token lab dan wiring `AppServices`;
  - batas 8 kartu (store dan HTTP);
  - penjaga `ACTIVE`/`SUSPENDED`, cabang undangan lain, cek kartu `REMOVED`;
  - cabang stdin CLI.
- Lab simulator, dengan PostgreSQL sementara dan API lokal:
  - undangan tanpa kartu fisik → `ACTIVE` dengan 1 kredensial;
  - perangkat 2 dengan token terpakai → "This invitation is invalid or has already been used.", tanpa instance baru, dengan respons identik untuk token acak;
  - perangkat 2 `PENDING_APPROVAL` menebus undangan berkartu (identitas lewat stdin) → instance yang sama `ACTIVE`, audit `enrollment.approved {from, method, invitation}`;
  - token dan identitas kartu tidak muncul di log API maupun dump database.

## Review akhir dan perbaikan

Hasil review: siap merge setelah perbaikan; 0 Critical. Perbaikan berikut dikerjakan dengan test RED lalu GREEN:
- **I1:** undangan berkartu buntu dengan `ENR-DUPLICATE` untuk instance perangkat sendiri yang belum selesai. Diputuskan JEV sebagai ADR-0035 (`promote_existing`, 0,94).
- **I2:** kartu `REMOVED` tetap bisa ditebus. Kini baris kartu dikunci dan undangannya tidak berlaku.
- **I3:** identitas kartu dan kontak di argumen CLI (riwayat shell, daftar proses). Kini lewat berkas atau stdin; kontak ditunda sampai FR-03.
- **I4:** batas 8 kartu di jalur undangan tanpa test. Test store dan HTTP ditambahkan.
- **M1, M5, M8** dinaikkan karena dampaknya: token lab berawalan `-` gagal tanpa pesan, `--zones` diabaikan sehingga zona bisa lebih luas daripada maksud operator, dan audit enrolment tanpa id undangan (requirement ADR-0035).

Ruling yang diambil:
- `-ANLabSite` tetap wajib bersama undangan.
- Bit sisa karakter terakhir token tidak diperiksa (selaras server).
- Perangkat lain boleh mengambil alih undangan yang instance-nya `ABANDONED` (ditinjau ulang saat ada akun).
- `InvitationLink` menerima bentuk longgar karena server yang memutuskan.
- Kredensial dan perpanjangan tidak memeriksa ulang status kartu (milik FR-51).

Minor tertunda: [backlog](../backlog.md) bagian Undangan.

`jev_gate` tereskalasi (composite 0,70, rubrik `test_gap`); klaim mutasi batas kartu kurang bukti nama test HTTP. Log: `docs/adr/jev-log/2026-11-01-undangan-gate.json`.
